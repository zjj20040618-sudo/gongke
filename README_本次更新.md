## 怎么用

1. MaixVision打开整个`03_扫码与物体识别联合App工程/qr_object_app`运行，不只传main.py；或安装`dist/maix-qr_object_switch-v2.1.12.zip`。同ID替换旧设备App，需要保留时先备份旧应用。
2. 默认扫码；USER短按进入物体识别，再短按回扫码。长按1.5秒退出。扫码成功不会自动切模式，等USER或MCU命令。
3. 扫码：灰度1920×1440、ZBAR、单相机缓冲。第一帧合法三码即LOCKED，每位只接受1～3；空帧、非法码、同帧不同码冲突不确认。切入扫码丢2个采集预热帧，和“合法二维码一帧确认”不是同一件事。
4. 扫码框可触屏移动，固定位置改QR_ROI_CENTER_X/Y；完整二维码和白边须在框内。保持原生灰度解码→缩到屏幕→转RGB画彩色框的顺序。
5. 物体：RGB888、9564十类模型实际输入尺寸，相机2缓冲＋模型dual_buff=True。无需扫码也能手动查看全部十类；点框独立显示/隐藏信息，不改变回传筛选。
6. MCU发60切模式、63切任务，视觉准备完成并完整写出ACK后才处理该请求。63只回指定类别，漏检配对帧发空目标；球、桶、靶、人质映射不变。

## 双缓冲不会把上一帧结果套到当前画面

`frame_pair.py`保存一张未画框的独立原图副本；detect返回上一张输入结果时，用对应原图画框、取坐标。新请求（即使仍是OBJECT）或成功手动切换清配对；首轮返回值丢弃、不发物体业务，第二轮才回传本请求ACK之后采集的帧。同号重试不清流水线。200毫秒HOLD只用于显示，不参与UART筛选。

双缓冲可能改善吞吐，但增加内存和约一帧结果延迟，不能保证固定FPS。`work/inference_ms`表示本次detect调用耗时，不是完整NPU延迟；`vision_ms`从被识别原图采集循环起点计至结果可用，包含流水线等待。源码、软件测试通过不能证明真实固件首帧行为或相机FPS，需上板核对。[官方双缓冲说明](https://wiki.sipeed.com/maixpy/doc/zh/vision/dual_buff.html)

## 手动切换与安全边界

MCU已接管后，USER仍可切换，但暂停本轮业务回传，屏幕提示`MCU PAUSED: NEW REQUEST REQUIRED`。旧同号重试回失败ACK和实际模式，不恢复任务；MCU须发递增新请求号重新接管。现有电控可能收到失败ACK后结束阶段，不承诺自动续跑。未接管时，手动识别UART只发已扫码任务的三类；无扫码任务发空目标包，不向主控混入全部十类。

USER长按退出或手动暂停不是电机急停。实车先通过电控停车，再诊断视觉；断流/停车由电控独立处理。01/53/60/63/61/62字节、CRC不变，但首个物体结果延后一轮以及手动暂停行为需双端联调确认。
