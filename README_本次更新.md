# 本次更新：扫码后自动识别对应目标

更新：2026-10-06。基线fae819c，App2.1.13，分支vision-task-filter-20261006。仅改正式03视觉App、必要测试及交接；不改App/电控，不上传、部署或烧录。保留用户物体字号2。

## 运行效果

1. 默认灰度扫码1920×1440、ZBAR；合法三码单帧锁存。
2. 完整发送三码后，下一轮自动切彩色OBJECT，无需再按USER。扫码未完整写出继续重发；模型加载失败留QR、保留任务、不每轮重载，USER或新请求可重试。
3. 独立01只回三码指定球、靶、人质，每类最高分一个；保留黑桶ID9持续回传要求。例331允许ID3/7/1/9，不发其他类别，丢目标回剩余目标或空包，不沿用HOLD坐标。
4. MCU接管60/QR时也自动打开OBJECT，但按原QR请求继续重复53，并显示WAIT MCU OBJECT REQUEST。MCU发递增新60/OBJECT或63、视觉完整ACK后才发绑定01；不会在QR请求下偷发坐标。
5. 通用OBJECT只发三任务＋桶，63每次只发指定类别，桶4/0持续发桶。双缓冲首轮不发01，新请求清配帧，同号重试不清。USER往返/暂停保护、触屏移动ROI和信息开关保持。

## 协议兼容和队友下一步

更新的是模式时序、筛选语义，不改变01/53/60/63/61/62字段、CRC、ACK、序号或请求号。当前App/proto.c按QR请求收53、OBJECT请求收01；保持既有31/32/33换请求流程即可，不需改解析器。不得删01的cy/w/h等字段来代替“电控只使用cx”。完整契约见VISION_TO_CONTROL.md“当前2.1.13”。

需要QR请求同号直接收物体数据时，必须另行审核、修改电控状态机/解析门控；本轮不授权电控框架改动。车静止验证三码、ACK、新请求和连续坐标，再按电控闸门进行运动联调。视觉退出/手动暂停不是电机急停。
