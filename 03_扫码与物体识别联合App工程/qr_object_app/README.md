# 正式扫码与十类物体识别 App

更新：2026-10-05。视觉回传协议升为v2：扫码只回“有效码已扫到”状态；物体回传类别ID和中心坐标，靶子只回中心X。当前电控解析器仍只认旧帧01/51，必须先更新电控接收代码和固件，v2才可联机。实机联调尚未完成。

## 1. 你的运行流程

1. 视觉开机 **IDLE 待机**，不自动启动任务。
2. 电控按写好的路线在二维码前停留，发送 QR 请求。
3. 视觉先回 ACK，再扫描；在视觉端锁存首个合法三位任务码，只向电控回报“尚未扫到/已扫到”状态，不发送任务码内容或二维码位置、大小。
4. 电控请求 OBJECT 后，视觉按内部锁存的任务码筛选球、靶、人质，并持续附带黑桶。每帧只发类别ID和中心坐标。
5. 电控在抓球阶段选球坐标；抓球后选黑桶坐标完成对位、放球。视觉不猜“已经抓球”，不自行控制电机。
6. 靶子只回中心X；其他目标回中心X/Y。黑桶只要本帧检测到，就在每个 OBJECT 结果帧发送。QR/IDLE 不做物体推理，不发送旧坐标。

**协议v2需要电控更新。** 当前 `App/proto.c` 只接收旧目标帧 `0x01` 和旧二维码帧 `0x51`，不会识别新帧 `0x02/0x52`。电控完成新解析器并烧录前，不要把视觉v2作为已联调版本使用。字段定义与队友修改项见根目录 [VISION_TO_CONTROL.md](../../VISION_TO_CONTROL.md)。

## 3. 二维码怎样选目标

任务码必须是三个字符，每位只能为 1、2、3：

- 第1位：球颜色，1红、2绿、3蓝；对应模型 ID4、5、3。
- 第2位：靶颜色，1红、2绿、3蓝；对应模型 ID6、8、7。
- 第3位：人质形状，1圆柱、2圆锥、3腰鼓；对应模型 ID1、2、0。
- 黑桶：固定模型 **ID9**，不由二维码选择，所有 OBJECT 帧都检查并发送。

本项目已经确认的训练别名：圆台体用于圆锥、扁圆物体用于腰鼓；不是通用几何等价关系。

例如 **123**：视觉内部选择红球 ID4、绿靶 ID8、腰鼓 ID0，以及黑桶 ID9；扫码串口只报状态，不发“123”。

同类多个框只返回置信度最高的一个，最多四个目标。无该目标就不包含它；四类都丢失时发空目标心跳，不造 (0,0)、不沿用上一帧坐标。每帧重新选择，黑桶丢失后不会重复旧坐标。

本轮任务码跨 IDLE 和新的 OBJECT 请求保留；只有成功的新 QR 请求才清空并重新锁存。相同请求重试只回原 ACK，不清任务、不重新加载模型；本轮扫到另一张合法码也不会悄悄改任务。

## 4. 类别、参数与坐标

模型 ID顺序：0扁圆物体、1圆柱体、2圆台体、3蓝球、4红球、5绿球、6红靶、7蓝靶、8绿靶、9黑桶。

`config.py`：

- 置信度阈值 0.35，单缓冲；类别标签加载时核对顺序。
- 字体大小 3，沿用你实测调整后的设置。
- 物体模式实际宽高读取模型输入。扫码 1600×900，中心宽、高各50%的区域，一次一个码。
- `MAX_OBJECTS=10` 限制画框/包上限；挑任务前不截断检测结果，避免干扰物挤掉指定目标和黑桶。

中心坐标为 `x+w//2, y+h//2`，单位像素，原点左上角。类别ID6、7、8的靶子只发送中心X；其他类别发送中心X/Y。OBJECT帧保留画幅宽高供电控校验坐标；不发送置信度、目标框宽高或毫米坐标。

终端 `[PERF]`：`task` 是锁存任务码，`sent_ids` 是本帧选入发送包的类别；`obj` 是检测框数，`qr` 是本帧二维码数。`cap` 取图、`work` 推理/扫码、`draw/display` 画框显示、`uart` 组包写调用、`loop` 单帧处理，单位毫秒。`loop` 不含模式切换和本行打印；fps包含循环、等待和日志影响。`sent_ids` 不等于 MCU 已收到或接受。

## 5. 协议v2

保留现有 `protocol.py`、`control_session.py`、`hardware.py` 的正式接口和行为：

- 电控请求 0x60，视觉确认 0x61，结果外壳 0x62。
- 目标内层 0x02，二维码状态内层 0x52；AA55 帧头，小端，CRC16/CCITT-FALSE。
- `0x52` 每帧带 `seq:u16, scanned:u8`；scanned=1表示视觉已锁存合法三位码，0表示尚未扫到。任务码和二维码几何不发送。
- `0x02` 固定头为 `seq:u16,count:u8,img_w:u16,img_h:u16`。目标ID6/7/8记录为 `class_id:u8,cx:u16`；其他ID记录为 `class_id:u8,cx:u16,cy:u16`。无目标时count=0。
- ACK 在新取图/业务结果之前发送；结果携带本轮 request_id；IDLE 不推理、不上报业务帧。
- 首次电控接管前的独立调试仍发送原裸帧；接管后使用带请求号的正式帧。
- A19/TX 接电控 RX，A18/RX 接电控 TX，115200、共地、3.3V 电平。
- 重启/断链后停止流程、清链路并重启两端，不自动续赛。

根目录 [VISION_CONTROL_PROTOCOL.md](../../VISION_CONTROL_PROTOCOL.md)、[VISION_INTEGRATION.md](../../VISION_INTEGRATION.md) 和 [VISION_TO_CONTROL.md](../../VISION_TO_CONTROL.md) 记录v2格式。当前电控解析器未升级，不能用旧帧接收证据代替v2联调。

视觉向电控的当前输出与交接见 [VISION_TO_CONTROL.md](../../VISION_TO_CONTROL.md)，每次视觉更新或协议核对后同步更新并推送。电控反馈写入其维护的 `CONTROL_TO_VISION.md`；该文件创建前读取现有 [VISION_TEAM_HANDOFF.md](../../VISION_TEAM_HANDOFF.md)。执行约定见 [AGENTS.md](../../AGENTS.md)。
